# MMBZalo Error Report: QR Image Capture Returns `null`

## Summary

The Zalo login browser can start successfully, but the public frontend still cannot show the QR code because the backend returns:

```json
{
  "state": "waiting_qr",
  "qr_image_base64": null
}
```

This means the login browser opens on the VPS, but the API does not capture and expose the QR image to the public UI.

## Product Goal

Real users should connect Zalo from the public domain only:

```text
User opens https://linhanhchip.site
→ registers/logs in
→ enters own workspace
→ clicks Connect Zalo
→ QR appears inside public web UI
→ user scans QR
→ VPS browser profile becomes authenticated
→ login browser auto-closes
→ user syncs contacts
```

Normal users should not need noVNC.

## Why the QR Must Come From the VPS Browser

The Zalo QR must be generated by the VPS Chrome profile because the VPS worker later reuses that same profile for contact sync and message sending.

Correct architecture:

```text
VPS Chrome profile
→ opens Zalo login page
→ receives QR challenge
→ backend captures QR screenshot
→ frontend displays that QR
→ user scans QR
→ Zalo authenticates VPS Chrome profile
→ worker reuses authenticated profile
```

Incorrect architecture:

```text
User opens Zalo locally
→ scans local QR
→ local browser gets authenticated
→ VPS profile remains unauthenticated
→ worker cannot sync/send
```

Therefore, the app should not ask users to open Zalo locally. It should display the VPS browser's QR image inside the frontend.

## What Is Still Broken

The QR image capture is not working.

Current broken behavior:

```text
/api/login/start → 200
state → waiting_qr
VPS login browser opens
qr_image_base64 → null
frontend has no QR image to render
user still cannot connect Zalo without noVNC
```

Expected behavior:

```text
/api/login/start → 200
state → waiting_qr
VPS login browser opens
qr_image_base64 → data:image/png;base64,...
frontend renders QR image
user scans QR from public domain
```

## Root Issue

The backend exposes the `qr_image_base64` field, but it does not populate it.

Observed API response:

```json
{
  "state": "waiting_qr",
  "message": "Waiting for QR scan or phone login...",
  "qr_image_base64": null
}
```

Possible causes:

```text
QR selector is wrong
QR element is not found
QR capture runs too early
QR capture failure is swallowed silently
Only exact QR capture is attempted, with no fallback
Screenshot/base64 encoding is not wired into LoginStatus
```

## Required Fix

Keep the VPS browser architecture, but fix QR capture.

When `state = waiting_qr`, the backend should attempt QR capture in fallback order:

```text
1. Try to capture exact QR element.
2. If QR selector fails, capture the whole login panel.
3. If panel selector fails, capture full page screenshot.
4. Return data:image/png;base64,...
```

For MVP, full page screenshot is enough.

MVP acceptable behavior:

```json
{
  "state": "waiting_qr",
  "qr_image_base64": "data:image/png;base64,iVBORw0KGgo..."
}
```

The frontend can display the returned image even if it is the full login page instead of a tightly cropped QR.

## Recommended Backend Logic

In the login status method or ZaloDriver status capture method:

```text
if state == waiting_qr:
    try exact QR selector screenshot
    if failed:
        try login panel screenshot
    if failed:
        try full page screenshot
    encode PNG as base64 data URL
    return qr_image_base64
```

Pseudo-code:

```python
async def capture_qr_or_login_page(page):
    selectors = [
        "img[src*='qr']",
        "canvas",
        "[class*='qr']",
        "[class*='login']",
    ]

    for selector in selectors:
        locator = page.locator(selector).first
        try:
            await locator.wait_for(state="visible", timeout=1500)
            png = await locator.screenshot()
            return "data:image/png;base64," + base64.b64encode(png).decode()
        except Exception:
            continue

    # MVP fallback: full page screenshot
    png = await page.screenshot(full_page=True)
    return "data:image/png;base64," + base64.b64encode(png).decode()
```

If the codebase still uses sync Playwright inside a dedicated owner thread, use equivalent sync calls inside the browser owner thread only.

## Logging Requirement

Add explicit logs when QR capture fails.

Useful logs:

```text
QR capture: trying exact selector
QR capture: exact selector failed
QR capture: trying login panel
QR capture: login panel failed
QR capture: falling back to full page screenshot
QR capture: success, bytes=<n>
QR capture: failed, reason=<exception>
```

Do not silently return `qr_image_base64: null` while state is `waiting_qr`.

## Frontend Requirement

The frontend should render the image when `qr_image_base64` is present:

```text
if state == "waiting_qr" and qr_image_base64:
    show <img src={qr_image_base64}>
else if state == "waiting_qr" and qr_image_base64 is null:
    show "Preparing QR..." and continue polling
```

Frontend should continue polling `/api/login/status` every 1-2 seconds until:

```text
qr_image_base64 is non-null
or state becomes authenticated
or an error occurs
```
